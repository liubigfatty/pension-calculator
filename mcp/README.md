# 养老金计算 MCP Server

把引擎的计算能力暴露给任意支持 MCP 的 AI（Claude / ChatGPT / Cursor / WorkBuddy / 微信 AI）。

## 为什么零依赖

引擎本身是零依赖纯 JS，再引 npm SDK 只会增加体积和打包环节。MCP 本质是 JSON-RPC 2.0 + 三个方法，
直接用 Node 内置 `http` 实现即可，也方便原样塞进云函数或 Workers。

- 传输：Streamable HTTP，**无状态模式**（不维护 session，不实现 SSE 流）
- 端点：`POST /mcp`
- 不支持的方法：`GET /mcp`、`DELETE /mcp`（返回 405，符合无状态模式约定）

## 跑起来

```bash
cd 养老金计算平台/mcp
node server.js            # 默认 http://127.0.0.1:8787/mcp
PORT=9000 node server.js  # 换端口
node _smoke.js            # 冒烟测试（需先起服务）
```

## 三个工具

| 工具 | 用途 | 必填 |
|---|---|---|
| `pension_calculate` | 测算月养老金及四项构成 | province, gender_type, birth_date, work_start_date, average_index |
| `pension_retire_date` | 查法定退休时间、延迟月数、最早可提前时间 | province, gender_type, birth_date |
| `pension_regions` | 查支持地区、某省是否分城市口径 | 无 |

入参接受中文：省份可填「吉林」「吉林省」「jilin」，性别可填「男」「女干部」「女工人」，
日期支持 `1976-02` / `1976年2月` / `197602`。别名映射从 `provinces-data.js` 动态反建，不写死列表。

## 边界（别破）

1. **只出基础测算这一档** —— 小程序本来就免费的部分。分档对比、回本测算、敏感性分析一律不开放，
   输出末尾固定引导去小程序。否则会冲掉 1 元付费。
2. **缺参数必须点名回问**，绝不猜、绝不填默认值凑数。
3. 输出固定「事实 + 动作 + 免责」三段，结果必须带"以社保经办机构核定为准"。

## 部署到哪

当前是本地进程。要对外服务：

- **国内优先腾讯云函数 SCF** —— Cloudflare 在国内访问不稳。把 `server.js` 的 `listen` 换成
  云函数入口（`exports.main = (event) => ...`，解析 `event.body` 后走同一套调度）。
- **海外 / Claude、ChatGPT 用 Cloudflare Workers** —— Free 版 10 万请求/天、脚本上限 3 MB
  （引擎 505 KB 够）、CPU 10 ms/请求（纯算术远低于，实测确认后再放量）。
- **微信生态走小程序 AI 开发模式** —— 那是另一套（SKILL = SKILL.md + mcp.json + 原子接口），
  代码跑在微信客户端，本目录的 HTTP 服务用不上。

## 文件

- `server.js` — HTTP + JSON-RPC 调度
- `tools.js` — 工具定义与执行（**description 是核心工作量**，决定 AI 会不会选中）

## 已修缺陷（都是自己测出来的，不是猜的）

1. **31 省有 16 个识别不了** —— 那 16 个省的 cfg 没有 `name` 字段，`province` 字段存的还是拼音，
   纯动态反建别名必然漏一半。已补中文兜底表。（初版只测了吉林/广东/北京，恰好都有 name，全漏了）
2. **协议版本虚报** —— 原实现把客户端要的版本原样回显，等于宣布支持 `2026-07-28`，
   而该版本已取消 initialize 握手、要求实现 `server/discover`，本实现都没有。改为只回真正支持的版本。
3. **未校验 `MCP-Protocol-Version` 头**（规范 MUST 400）、**未校验 `Origin`**（DNS rebinding，规范 MUST 403）。
4. **`parseMonth` 年份写死 1930–2015** —— 对出生年月成立，对**退休年月**不成立（退休可是 2038 年）。
   已按用途拆分范围。这个雷只有加了 `retire_date` 参数才暴露。

## 已知准确度边界（必须如实告知用户）

以 `cases/` 28 个省案例为基准（引擎自身 185/185 无误，偏差全部来自 MCP 只收"用户说得出的参数"）：

- **正常到龄退休**：偏差 ≤5% 占 **61%**，≤10% 占 **75%**
- **主要偏差源**：退休年份判错（提前退休 / 特殊工种 / 西藏女工 45 岁等地区政策）、
  视同缴费年限的档案认定差异、断缴与跨省转移
- **典型**：湖北案例差 83%（案例实际缴费 24.5 年，MCP 按连续参保推成 43.75 年）——
  这类差异用户不主动说明就无解，故输出中固定带「【适用边界】」提示段

⚠️ 结论：本工具定位是**粗估**，适合回答"大概什么量级"，不能替代社保经办核定。
用户若说明提前退休/断缴/特殊工种，准确度可显著提升。
