# 待办：加发项输入改造（含四川独生子女默认发证）

> 登记时间：2026-09-20　｜　状态：**待启动（等输入改造一并进行）**
> 触发背景：2026-09-19 引擎审计发现四川独生子女增发默认发证；用户拍板「先按默认发证算，后续加发这块会涉及到输入改造，到时候一起做」。

---

## 一、为什么现在不动

引擎 `calcExtraPension()` 里四川分支的判断是：

```js
const oneChild = params?.oneChild !== false   // 默认有独生子女(向后兼容)
```

即 **`oneChild` 未传（undefined）时按「有独生子女」走公式**，只有显式传 `false` 才转定额补贴。
这是当年为兼容旧 case（无 `oneChild` 字段）留的向后兼容开关。

改成「默认不发证」会同时影响：
1. 7 个四川历史 case（无 `oneChild` 字段）→ 全部少一笔增发，期望值要重标定；
2. 主程序 / 网页 / 小程序三端 UI 都得先有「是否持有《独生子女父母光荣证》」的输入项，否则用户无法拿回这笔钱。

**所以正确顺序是：先做输入端改造 → 再翻转默认值 → 再重标定 case。** 现在只做输入端，默认值保持不变。

---

## 二、改造范围（一次做完，不只四川）

四川不是孤例。审计发现全引擎共 **6 类条件性待遇**依赖用户输入，其中 4 类目前没有稳定输入通道：

| # | 省 | 项 | 当前触发条件 | 缺什么输入 |
|---|---|---|---|---|
| 1 | 四川 | 增发养老金（独生子女 0.1%×年限 等合计 0.1%~0.4%） | `oneChild !== false`（默认发证） | 独生子女证 / 2005年底前工作 / 艰苦边远 三类勾选项 + `extraRate` |
| 2 | 重庆 | 独生子女增发 3% | `data.oneChild` | 独生子女证勾选 |
| 3 | 贵州 | 独生子女父母奖励 5% | `data.oneChild`（2026-09-19 已补） | 独生子女证勾选 |
| 4 | 海南 | 计划生育奖励 5% / 10% | `data.oneChild` + `oneChildType` | 独生子女父母 / 无子女 二选一 |
| 5 | 云南 | 独生子女补贴 = 人均养老金×5% | `data.oneChild` | 独生子女证勾选 |
| 6 | 宁夏 | 知识分子补贴 10+8.5 元 | `data.intellectual` | 知识分子身份勾选 |

**统一改造方案**：在输入层加一个 `benefits`（待遇资格）对象，字段固定为

```js
benefits: {
  oneChild:        true | false | null,   // null = 未表态（沿用各省默认）
  oneChildType:    'parent' | 'no_child', // 海南专用
  intellectual:    true | false,          // 宁夏专用
  hardshipArea:    true | false,          // 四川艰苦边远 0.1%
  workedBefore2005:true | false,          // 四川 2005 年底前工作 0.1%
  tibetWorkYears:  number,                // 西藏在藏工作年限（高原补贴分档）
  regionCategory:  '二类地区' | ...        // 西藏地区类别
}
```

三端（云函数 / `web/` / `miniprogram/`）共用同一套字段，`parseInput()` 统一解析。
