## 三、P2 · 阶梯公式少算 1 个月

### 政策依据

国办发〔2025〕5号附件对照表（男职工）：

| 出生时间 | 法定退休年龄 |
|---|---|
| 1965 年 1 月—4 月 | 60 岁 1 个月 |
| 1965 年 5 月—8 月 | 60 岁 2 个月 |
| 1965 年 9 月—12 月 | 60 岁 3 个月 |
| …… | …… |
| 1976 年 9 月及以后 | 63 岁 |

### 公式推导

`diff = (出生年 − baseYear) × 12 + (出生月 − 1)`

正确：`delay = min(floor(diff / step) + 1, cap)`
- 1965-01 → `floor(0/4)+1` = **1** ✓
- 1965-05 → `floor(4/4)+1` = **2** ✓
- 1976-09 → `floor(140/4)+1` = **36** ✓（正好 63 岁）

原实现：`delay = min(floor((diff − 1) / step) + 1, cap)`
- 1965-05 → `floor(3/4)+1` = **1** ✗（少 1）
- 1976-09 → `floor(139/4)+1` = **35** ✗

### 修改

```js
const diff = (birthYear - baseYear) * 12 + (birthMonth - 1)
if (diff < 0) return 0                       // 原为 diff <= 0
const delay = Math.floor(diff / step) + 1    // 原为 (diff - 1)
return Math.min(delay, cap)
```

边界同步调整：原 `if (diff <= 0) return 0` 会让基准月（1965-01）返回 0，须改为 `diff < 0`。

## 四、D1 · 退休日期年份不进位（本次评估中发现的更严重问题）

### 现象

| 出生 | 引擎 `date` | 引擎 `ageStr` | 正确退休时间 |
|---|---|---|---|
| 1965-01 | 2025-02 | 60岁1个月 | 2025-02 ✓ |
| 1965-06 | 2025-08 | 60岁2个月 | 2025-08 ✓ |
| **1965-12** | **2025-03** | **60岁3个月** | **2026-03** ✗ |

`ageStr` 说「60岁3个月」，`date` 却给 `2025-03` —— **同一次返回内自相矛盾**。

### 原实现

```js
const year = birthYear + Math.floor(totalMonths / 12)
const month = birthMonth + (totalMonths % 12)
return { year, month: month > 12 ? month - 12 : month }   // 月份回拨了，年份没进位
```

### 污染链（这是最严重的地方）

`legalDate` 不只用于显示：

| 用途 | 位置 |
|---|---|
| 缴费年限 `autoTotalYears = calcYears(actualStart, legalDate)` | `pension-engine.js:1668` |
| 计发基数取值 `getBase('prov'/'city', legalDate.year)` | `:1765` `:1768` |
| 社平取值 `'social_avg_' + (legalDate.year - 1)` | `:1777` `:1781` |
| 最低缴费年限 `getMinYears(legalDate.year)` | `:2030` `:2031` |
| 弹性提前退休日期 `flexDate` | `:1640` |

实测 1965-12 出生的男职工：缴费年限 **24.67 年**（应为 25.67 年）。

### 修改

```js
const t = birthYear * 12 + (birthMonth - 1) + totalMonths
return { year: Math.floor(t / 12), month: (t % 12) + 1 }
```

### 暴露条件

`birthMonth + (totalMonths % 12) > 12` 时触发。走 `retireDateInput` 的路径不受影响（用户直接给退休年月），只有**自动推算退休时间**才会踩到。

### 出处

来自项目**第一个提交** `c1cd73e`，从未改过。

## 五、D2 · fw55 参数用错人群

### 现象

`getDelayMonths` 默认分支给 `fw55` 配的是 `baseYear=1975, step=2, cap=60` —— 那是**原法定 50 岁女工人**的参数，而 `fw55` 的 `baseAge` 是 **55**，自相矛盾。

### 根因

`ace9938` 的提交说明写着：

```
1. engine/pension-engine.js 两个修复:
   - fw55默认参数: baseYear=1975→1970, step=2→4, cap=60→36 ✅
```

但 `git show ace9938 -- engine/pension-engine.js` **没有任何 diff 输出** —— 该提交**只删除了 31 省的 `delay_retirement` 配置，并未改动引擎文件**。

结果：省级配置（`female_worker: 1970/4/36`）被删，引擎默认值又是错的（`1975/2/60`）→ **参数净丢失**。

### 修改

```js
case 'fw55':
  baseYear = 1970; step = 4; cap = 36   // 原法定 55 岁 → 逐步延至 58 岁
```

### 影响面

| 出生年月 | 修复前 | 修复后 |
|---|---|---|
| 1970-01 | 2025-01 | 2025-02 |
| 1970-05 | 2025-06 | 2025-07 |
| 1981-09 | 58岁5个月 | 58岁 ✅ |

量化：**310/432（71.8%）** 的出生年月结果变化。
