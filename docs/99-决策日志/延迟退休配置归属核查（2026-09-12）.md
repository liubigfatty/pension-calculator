# 延迟退休配置归属核查：该全国统一，还是按省配置？

> 核查日期：2026-09-12
> 触发：用户质疑「延迟退休的年龄应该是全国配置生效的，为什么现在会改到各省生效呢」
> 结论：**用户是对的。全国统一是既定设计，且现在实际生效的就是引擎里的全国统一配置。省级配置是两次历史动作留下的残留，其中 1 份仍在生效且带错值。**

---

## 一、结论先行

| 问题 | 答案 |
|---|---|
| 延迟退休参数该按省配吗？ | **不该**。国办发〔2025〕5号是全国统一政策，base_year / step / cap_months 全国一致 |
| 现在实际生效的是什么？ | **引擎内硬编码默认值**（`pension-engine.js:1063-1085`），31 省共用 |
| 为什么到处能看到省级配置？ | 2026-07-03 有一次「批量下发到 29 省」，26 分钟后被推翻并回收；`*.json` 副本没清干净 + 四川漏删 |
| 有实际影响吗？ | **有 1 处**：四川（唯一漏删的省），2025 年退休人群延迟月数被清零 |

---

## 二、时间线：26 分钟内的一来一回

同一天（2026-07-03），两次方向相反的提交：

| 时间 | 提交 | 动作 | 方向 |
|---|---|---|---|
| 21:34 | `042b405` | 批量给 **29 省 `.js`** 加 `delay_retirement.female_worker`（base_year=1970, step=4, cap=36） | 政策参数**下发到省** |
| 22:00 | `ace9938` | 「延迟退休参数统一在引擎处理 + 各省已删除」——参数改到引擎默认值，**31 省 `.js` 删除 `delay_retirement`** | **回归全国统一** |

`ace9938` 的提交说明（原文节选）：

```
1. engine/pension-engine.js 两个修复:
   - fw55默认参数: baseYear=1975→1970, step=2→4, cap=60→36
   - originalAge switch 补充 case 'fw55': 修复弹性提前60岁bug
2. 31省 .js 删除 delay_retirement 配置（由引擎统一处理）
```

**所以「改到各省」只存在过 26 分钟，方向早已纠正。** 用户记忆中的「应该全国配置」是准确的，那正是 `ace9938` 确立的原则。

> 附带发现：`042b405` 下发的参数本身也是错的——给 `female_worker` 键配的是 1970/4/36（**女干部**的参数，延到 58 岁），而女工人应为 1975/2/60（延到 55 岁）。它前一个提交 `046fade` 标题「修复fw55延迟退休参数（企业女职工原55岁）」说明当时把「企业女职工 55 岁」错当成了「女工人」。这也是 26 分钟后被 `ace9938` 推翻的原因之一。

## 三、现在还能看到省级配置的三层原因

### 第 1 层：`provinces/*.json` 副本 —— 死数据，运行时零加载（26 省）

- **真相源是 `provinces/*.js`**。构建脚本 `scripts/build-cloud-provinces.js` 第 23 行：
  ```js
  const files = fs.readdirSync(SRC_DIR).filter(f => f.endsWith('.js')).sort()
  ```
  只读 `.js`，`.json` 从不参与生成。
- 全仓库搜索 `.json` 的实际加载点：只出现在 `tests/` 和 `scripts/`（做单测/文档生成），**没有一处运行时加载**。
- 实测：`getConfig('jilin').delay_retirement` → `undefined`。

### 第 2 层：`sichuan.js` —— 唯一活得省级配置，且带错值（1 省）

- `ace9938` 的批量删除脚本只匹配字面量 `delay_retirement: {...}`；四川写的是**常量引用** `delay_retirement: DELAY_RETIREMENT`（`sichuan.js:167-172, 238`），**漏删**。
- 统计印证：`git show ace9938 --stat` 的 `provinces/` 变更数为 **30 个**（31 − 1）。
- 它带的 `effective_date: "2026-01-01"` **是错的**——政策 2025-01-01 施行。

### 第 3 层：引擎硬编码默认值 —— 这才是实际生效的「全国统一配置」

`pension-engine.js:1063-1085`：

```js
const delayKeyMap = { 'male': 'male', 'fc': 'female_cadre', 'fw': 'female_worker', 'fw55': 'female_worker' }
const typeConfig = delayConfig[delayConfigKey] || {}
if (typeConfig.base_year !== undefined) { ... 用省级参数 }
else {
  switch (type) {
    case 'male': baseYear = 1965; step = 4; cap = 36
    case 'fc':   baseYear = 1970; step = 4; cap = 36
    case 'fw55': baseYear = 1970; step = 4; cap = 36   // 已由 ace9938 修正
    case 'fw':   baseYear = 1975; step = 2; cap = 60
  }
}
```

30 省（除四川）的 config 里没有 `delay_retirement` → 走这份默认值 → **全国一致**。

## 四、四川实证：唯一有实际影响的省

同出生年月、同人员类型（男职工），三地实测退休时间：

| 出生年月 | 四川（现状） | 四川（修正后） | 吉林（引擎默认） |
|---|---|---|---|
| 1965-01 | 2025-01 | 2025-01 | 2025-01 |
| 1965-05 | **2025-05** | 2025-06 | 2025-06 |
| 1965-09 | **2025-09** | 2025-11 | 2025-11 |

**成因**：`sichuan.js` 的 `effective_date: "2026-01-01"`，让引擎在 `pension-engine.js:1042-1047` 判定「法定退休日期 < 生效日期 ⇒ 不延迟」，把**整个 2025 年退休的人群**判成政策未生效。

**影响面**：四川 2025 年退休测算，延迟月数被清零（1965-05 生少 1 个月、1965-09 生少 2 个月）。退休时点前移会同时影响计发月数、个人账户、缴费年限。

## 五、顺带查出：省级该配的其实是另一个字段

引擎里**确实存在一个合理的省级差异化配置**：`flex_retire_age`（灵活就业退休年龄覆盖）。

- 目前只有 **西藏** 配了（`xizang.js`：男 55 / 女 45，藏政发〔2006〕37号等依据）
- 引擎处理位置：`pension-engine.js:1108-1116`、`1146-1153`
- 注释明确：「仅当该省份配置 `flex_retire_age` 时生效，不影响其他省份」

**两类配置要分清**：

| 配置 | 性质 | 该放哪 |
|---|---|---|
| `delay_retirement`（base_year/step/cap） | 国办发〔2025〕5号，全国统一 | **引擎**（当前状态正确） |
| `flex_retire_age` | 地方性退休年龄差异（如西藏） | **省级**（当前状态正确） |

当初把两者混在一起，可能正是「延迟退休参数下发到省」的认知来源。

## 六、引擎延迟退休的现存缺陷（本次核查确认，均未修）

| # | 位置 | 问题 | 影响面 |
|---|---|---|---|
| 1 | `sichuan.js:168` | `effective_date` 写成 `2026-01-01`（应 2025-01-01） | **四川 2025 年退休人群**，线上 |
| 2 | `pension-engine.js:1029` | `if (type === 'fw50' \|\| type === 'fw' \|\| type === 'ef50') return 0` —— 在读取配置**之前**短路，为 `fw` 备好的参数永远走不到 | 原法定 50 岁女职工**完全不延迟**，与政策不符 |
| 3 | `pension-engine.js:1088` | `Math.floor((diff - 1) / step) + 1`，政策原文应为 `Math.floor(diff / step) + 1` | 出生月落在**档位起始月**（男/女干部 1/5/9 月，女工人奇数月）时**少算 1 个月** |
| 4 | 26 省 `*.json` | `delay_retirement` 死数据，键名两套并存（24 省 `fc`/`fw55`，黑/川/滇 `female_cadre`/`female_worker`） | 无计算影响，但会误导后续排查 |

> 关于 #4 的键名：`delayKeyMap` 把 `fc`→`female_cadre`、`fw55`→`female_worker`，所以 24 省那套 `fc`/`fw55` 键名引擎**根本认不出**。但即使认出也读不到——源 `.js` 里本来就没有。属于「三层都断了」。

## 七、修复建议（分优先级）

| 优先级 | 动作 | 理由 |
|---|---|---|
| **P0** | 四川 `effective_date` 改 `2025-01-01`，**或直接删除四川的 `delay_retirement`**（回归引擎统一） | 线上 bug，2025 年退休人群结果错误 |
| P1 | 清理 26 省 `*.json` 的 `delay_retirement` 死数据 | 防再次误读/误同步 |
| P2 | 引擎阶梯公式 `(diff-1)` → `diff` | 影响所有省份档位起始月人群 |
| P3 | 移除 `fw50/fw` 的 `return 0` 短路 | 政策上原 50 岁女职工同样延迟；需确认产品口径 |

**建议 P0 立即处理，P2/P3 单独立项**——它们会改变存量测算结果，需评估影响面后再动。

## 八、方法论（写进技能，避免重复踩坑）

排查「这个配置到底在哪生效」时的固定四步：

1. **查全两层文件**：`provinces/*.js`（真相源）与 `provinces/*.json`（副本），别只 grep 一层。
2. **找构建脚本的读取源**：`build-cloud-provinces.js` 的 `filter()` 决定了谁进产物。
3. **实测 `getConfig()` 的返回值**：不问「文件里有没有」，问「运行时拿到什么」。
4. **`git log -S` 溯源**：字符串出现次数变化的提交列表，能直接看出「什么时候加、什么时候删、哪次漏删」。
